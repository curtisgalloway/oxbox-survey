## Voice, as directed by the user across the review rounds

Standing direction for every edition, in the user's words where possible:

- "Always be humble; we're just doing little toy tests right now." Claims carry
  their sample size; "at least a little evidence", never "evidence".
- "Try to always give context on why you should care about this paragraph." Every
  highlight: bold headline, then an italic *Why you should care:* line first,
  then the body.
- "Too much inside baseball" / "not interesting for a reader": the survey's own
  debugging and process never lead; one-sentence method caveats at most.
- "'Unchanged' is not interesting."
- "It's too early to comment too much on 'this is the first time we saw X'."
- "Let's lead with punchy facts for each model": a headline-fact line under each
  recommended model; the rate is "success rate".
- "Explain what this is" for jargon; link a longer page where one exists.
- "Let's clearly delineate the ones that worked vs. the ones that didn't."
- "Nobody is using oxbox, omit this": no version-floor or install talk.
- "Let's omit this till I have such advice": no hooks to advice not yet written.
- "In future we should strive to only report what's reviewed so we can generate
  a rate."
- Cost material sits before the model list, with a relative-cost yardstick
  against a strong paid model (Opus 5 proposed) where it makes sense, at list
  prices, labelled as an upper bound.
- From 2026-08-27: cut em-dashes and italics (the why-care label is the one
  sanctioned italic), spell out abbreviations, K/M figures in prose, link
  sources inline ("we're not journalists"), no repo paths in reader-facing text.

- From the r5 review: "K/M/G rounding in the paragraphs, full numbers in the
  extended model lists." The term for the served context figure is **context

## The relative-cost yardstick (added on the r4 review)

The user asked for "some metric for savings or relative cost, basically how
much cheaper is using this than using e.g. Opus 5 directly". Issue 1 defines it
as follows, to be repeated every edition so the ratio has a series:

- **Inference avoided**: the free run's prompt and completion tokens priced at
  Claude Opus 5 list rates, read from Anthropic's pricing page on the day of
  writing (2026-09-01: $5 in, $25 out per million). Stated as an assumption
  that Opus would have used the same token counts; its tokenizer differs.
- **Cost to check**: the reviewer's tokens from `costcheck.py`, priced at the
  reviewing model's list rates (Opus 5 $5/$25, cache read $0.50; Fable 5.1
  $10/$50, cache read $0.25, 5-minute cache write 1.25x input), per finding
  checked and per real finding. Always labelled an upper bound.
- **The ratio** of the two. Issue 1's matched pair: about $1 avoided, about
  $14.70 to check, roughly 15x. Cache reads were $6.22 of the $14.70.

Open question for the user: Opus 5 versus Sonnet 5 ($2/$10) as the basis, and
whether to print dollars or only the ratio.
