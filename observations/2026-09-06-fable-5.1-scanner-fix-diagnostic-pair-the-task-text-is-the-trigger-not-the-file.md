# The scanner-fix diagnostic pair on Fable 5.1: the pattern list alone is refused under the scanner prompt, and the full `ox` is reviewed under a neutral one, so the task text is the trigger

**What happened** — At the editor's direction, the two halves of the refused
request were separated. Run A sent the original `oxbox-secret-scanner-fix`
prompt with a payload that was only the eleven-line `SECRET_PATTERNS` list
extracted from `ox` at `6072d56` (564 bytes). Run B sent a neutral review
prompt ("Review this file for correctness bugs, security issues, resource
leaks, race conditions and incorrect error handling. Python 3.9+, standard
library only.") with the full `ox` at the pin (39,467 bytes), the same
payload the refused runs carried. Same model, venue, effort and temperature
as the three refusals.

| Run | Prompt | Payload | Outcome |
|---|---|---|---|
| A `2026-09-06T22-46-08Z` | the scanner-fix task | pattern list only, 564 B | **refused**: `content_filter`, no tokens billed |
| B `2026-09-06T22-46-11Z` | neutral review | full `ox`, 39,467 B | **answered**: `finish_reason` stop, 14,401 prompt, 8,474 completion (5,462 reasoning), $0.5677 billed, provider Anthropic, 18 findings |

With the morning's three refusals (original prompt, twice; motivated prompt,
once; all against the full file) the grid is complete: the scanner-fix task
text is refused against either payload, and the file is reviewed under a
different task. The trigger is the prompt.

## Evidence

Run A, `oxbox-send`: `finish=content_filter prompt_tokens=None
completion_tokens=None reasoning_chars=0`, exit 1, `venue_cost` null. Run B,
`status.json`: `ok` true, `finish_reason` stop, `venue_cost` 0.56771. Its
`content.md` opens with two findings on `send_and_parse`'s exception
handling (non-`URLError` exceptions raised while reading the body escape the
handler, so no `error.txt`, no failover, and a stale in-progress status
record) and runs to eighteen numbered findings. None has been verified; this
observation is about the refusal, and run B's findings are a by-product
recorded here so they are not lost.

## So what

**The prompt is the trigger, and it can be reworded only by changing the
task.** The scanner-fix prompt asks the model to make a credential detector
match six more credential shapes and lists them. That request, not the
source file, is what Anthropic's classifier refuses, and stating the
defensive purpose first did not change it (the same-day motivated variant).
The fixture keeps a null Fable ceiling; the survey now knows exactly why,
and knows that Fable will review `ox` itself without objection.

**A real by-product.** Run B is the first Fable 5.1 review of `ox` in the
record: eighteen findings for $0.57 in 108 seconds, unverified. If the
survey wants a Fable baseline on a review of `ox`, it exists; verifying it
under the reproduce-first rule is a separate piece of work and is not done
here.

**What this does not say.** Whether a smaller or differently worded
detector-maintenance task would pass. One task text was tested in two
framings against two payloads; the classifier's boundary is not mapped, and
mapping it is not the survey's job.
