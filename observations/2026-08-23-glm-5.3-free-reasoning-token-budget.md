# glm-5.3-free spends reasoning tokens on everything, and they count against max_tokens

**What happened** — asked to reply with the literal string `OK`, the model spent
29–30 completion tokens on reasoning. At `max_tokens: 32` the reasoning consumed
the entire budget and the response came back with **empty content and no error**.

## Evidence

`max_tokens: 32`:

```
HTTP 200
content: ''
usage: {"completion_tokens": 32, "prompt_tokens": 17,
        "completion_tokens_details": {"reasoning_tokens": 29}}
```

`max_tokens: 512`, same prompt:

```
HTTP 200
finish_reason: stop
content: 'OK'
reasoning field present, 141 chars
usage: {"completion_tokens": 35, "prompt_tokens": 17,
        "completion_tokens_details": {"reasoning_tokens": 30}}
```

## So what

Reasoning tokens are billed against `max_tokens`, so an under-budgeted call fails
**silently** — HTTP 200, no error field, empty string. Anything parsing this
endpoint must treat empty content as a failure mode rather than an empty answer.
`ox` defaults to `--max-tokens 32000`, so it is not exposed; a small-budget helper
call would be.

Weak evidence on the Ox Alpha attribution question, recorded because it is
cheap to record and will matter if a pattern accumulates: issue 0.1 reports Ox
Alpha returning `reasoning_chars=0` on short calls, while GLM-5.3 returned
reasoning on the shortest prompt available. If the two were the same model behind
the same defaults, they would be expected to agree. **This is one trivial prompt
against each and settles nothing** — the real test is a side-by-side review of
one file, which needs `--base-url` in oxbox first.
