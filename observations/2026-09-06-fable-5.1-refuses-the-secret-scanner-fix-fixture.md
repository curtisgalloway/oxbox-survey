# Fable 5.1 refuses the secret-scanner fix: `content_filter`, twice, no tokens billed, so this fixture has no cost ceiling

**What happened** — `oxbox-secret-scanner-fix` (`ox` at `6072d56`, 39,467 B,
`--mode diff`) put to `anthropic/claude-fable-5.1` to set the fixture's cost
ceiling. The venue returned no content: `finish_reason` `content_filter`,
`native_finish_reason` `refusal`, and a refusal message citing Anthropic's
usage policy on "violative cyber content". Retried once, two minutes later,
same result. Both responses returned in about two seconds with no token
counts, so nothing was billed.

## Evidence

Runs `logs/2026-09-06T21-22-21Z` and `logs/2026-09-06T21-24-24Z`, identical
payloads (`context_bytes` 39467), identical outcome. From the first
`response.json`:

```
"finish_reason": "content_filter",
"native_finish_reason": "refusal",
"message": {
  "role": "assistant",
  "content": null,
  "refusal": "This request triggered restrictions on violative cyber content
  and was blocked under Anthropic's Usage Policy. To learn more, see
  https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback
  ..."
}
```

ox's own report: `ox: finish=content_filter prompt_tokens=None
completion_tokens=None reasoning_chars=0`, exit 1, `status.json` `ok` false.

The prompt asks for a regex fix to a secret scanner and lists the credential
assignment forms it must catch, with every value written as `<n chars>` so
that the task text does not itself trip the scanner. The payload is `ox` at
the pin, which contains the pattern list and nothing resembling a live
secret. Five other models answered the same bytes on 2026-09-02 without
comment.

## So what

**This fixture cannot carry a Fable 5.1 ceiling.** The Editor's Rating
decision measures the cost digit against Fable's cost per hit on the same
fixture, and Fable will not produce a hit here. `cost_ceiling_usd_per_real`
stays null on `oxbox-secret-scanner-fix` and the cost column on that fixture
stays a dash, for every model, until either the classifier changes or the
survey re-decides the ruler for diff-mode fixtures. Recorded rather than
worked around: a different ruler for one fixture would make the cost digits
incomparable across fixtures, which is the thing they were built to be.

**A refusal is a property of the fixture, not the model, and is not a
disqualifier.** Fable answered the other two fixtures the same minute. This
file carries no `disqualifier` field because that column is for a venue
refusing a model, and a standing entry would wrongly hold the model out of
every table; the refusal lives in the corpus task's notes instead.

**For the pipeline it is a data point of its own kind.** A frontier model
declined a maintenance task on a secret scanner because the task describes
what secrets look like. Any reader pointing ox at security tooling should
expect the same from this route, and the survey should say so when it next
lists the model.
