# Qwen 3.8 27B, local, as a candidate on the zero-defect control: nothing in 900 seconds on a Mac Studio

**What happened** — `oxbox-clean-control`, the zero-defect control
(`jailtest.py` at `6302b12`, 6,096 B, review mode, effort high, 100,000
tokens, temperature 0.2), put to `qwen3.8:27b` (Q4_K_M, 17.7 GB) served by
ollama 0.34.0 on argenta, a Mac Studio M3 Ultra with the 60-core GPU and 96 GB.
The first local run of the survey. oxbox's 900-second read timeout closed the
connection with no answer, no token count and no bill. The same payload, sent
again with the timeout raised to an hour, answered in 1,557 seconds; see
`2026-09-10-qwen3.8-27b-local-candidate-zero-defect-control-ten-findings-two-real-in-26-minutes.md`.

## How the local runs were made

ollama serves an OpenAI-compatible endpoint at `/v1/chat/completions` over
plain http on the LAN, and the released `oxbox send` refuses a plaintext
`--base-url` because a credential must not travel in cleartext. The runs used
a debug build of `oxbox-send` 1.3.0 with its `test-overrides` feature, which
lets `OXBOX_TEST_ALLOW_HTTP=1` lift that one check; the request path, the
system prompt, the payload and the audit log are the release's. The key
variable named by `--api-key-env` held a placeholder, since ollama checks
none. `venue` in the run's `meta.json` is `custom`; the survey records it as
`ollama`. Every local run in this batch shares that setup; this one is the
only run at the release's 900-second timeout.

The server had no context cap set, so it loaded the model at its full 262,144
context (`/api/ps` `context_length`). A 44,016-token probe prompt went in
untruncated at 237 tokens per second of prefill.

**Server settings** — ollama 0.34.0 with no `OLLAMA_CONTEXT_LENGTH` set, so the model loaded at `num_ctx` 262,144, its full architectural context (`/api/ps` `context_length` read during the run). The OpenAI-compatible endpoint takes no `num_ctx` from the request, so the fixture could not lower it. Read timeout 900 seconds, the release's.

## Evidence

Log `logs/2026-09-10T22-43-07Z`: `request.json` and `meta.json` only, no
`response.json`; `status.json` `ok` false, `error` "oxbox-send: timed out
after 900s reading the response (global)". The driver's stderr:

```
oxbox-send: venue=custom model=qwen3.8:27b mode=review effort=high context=6096B files=1
oxbox-send: timed out after 900s reading the response (global)
```

## So what

At the survey's standard contract this model does not answer a 6 KB review on
this hardware. The re-run shows why: 27,306 completion tokens at about 17.5
tokens per second, three quarters of them reasoning. The hosted models that
timed out on this fixture (gpt-oss-120b and North Mini Code on 2026-09-08) did
so on shared pools; this one is alone on a 96 GB machine and is simply slow.
Speed is an axis the catalog table scores, and a reader running a dense 27B
model at home should read `wall_s` as the cost.

## Cost

Nothing billed, nothing to read. The price of a local run is the hardware and
the wall clock.
