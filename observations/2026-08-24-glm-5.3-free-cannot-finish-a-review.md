# glm-5.3-free burned 32,000 tokens on one review and produced nothing

**What happened** — the third arm of the matched comparison. Same 13.6KB file,
same prompt, same `--mode review`, same `ox` parameters as
[[2026-08-24-ox-alpha-found-a-real-credential-leak]] and
[[2026-08-24-leanstral-review-same-file-zero-real-findings]]. At `ox`'s full
default budget it returned **empty content**.

```
completion_tokens=32000  of which reasoning_tokens=31995
content.md: 0 bytes
reasoning.txt: 127,380 characters
```

## This corrects my previous correction

[[2026-08-24-correction-glm-5.3-reasoning-is-inconsistent]] concluded the
earlier empty review was self-inflicted, because I had lowered `--max-tokens` to
8000, and that "the default is well-chosen for this class of model". **That is
false.** At the default 32000 it also returned nothing, with the same 99.98%
reasoning ratio. The budget was never the problem.

Two runs, two budgets, same outcome:

| max_tokens | reasoning | content |
|---|---|---|
| 8000 | 7995 (99.9%) | empty |
| 32000 | 31995 (99.98%) | empty |

## What the reasoning shows

It is coherent English, not a degenerate loop, and it starts correctly — tracing
the venue logic against the stated security intent. It then spirals into
unresolvable trivia and never converges. The trace ends mid-thought on **Python
2** semantics:

> `I don't remember. BUT — Python 2's urllib DOES have: ... Hmm, that's
> IOError('url error', 'unknown url type', type) — not ValueError. OK so where's
> the ValueError?! Let me think about`

The bitter detail: it was circling the **same defect Ox Alpha reported as
finding #2** — that a scheme-less `--base-url` raises `ValueError` at request
time. It was in the right territory and could not close.

## So what

**On this task, at any budget tested, this model cannot produce a review.** Not
a quality problem — an output problem. The catalog cannot see it: 1M context,
`response_format` support, a clean listing. Only running it shows this.

**And it is evidence against the Ox Alpha attribution, this time properly
matched.** On identical input, `x-preview-f-free` spent 4,935 reasoning tokens,
converged, and returned five real findings; `z-ai/glm-5.3-free` spent 31,995 and
returned nothing. That is a large behavioural divergence between the model and
its suspected identity.

Held loosely, for a real reason: the two calls went through different venues,
and a venue may translate `reasoning: {"effort": "high"}` differently before it
reaches the model. Same nominal parameters do not guarantee same effective ones.
Testing that needs both models behind one venue, which nothing currently offers.

Also: `ox` writes a 0-byte `content.md` with no warning here. An empty
completion is indistinguishable from a failure at the log level, and a caller
scripting against `content.md` gets a silent no-op. Worth an explicit warning.
